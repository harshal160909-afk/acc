# Deploying ACC to Cloudflare

ACC runs as a **Cloudflare Worker** with a **D1** database (binding `DB`). It is
not a static site and cannot run on Netlify/Vercel static hosting. The build
(`npm run build`) emits a deployable Worker at `dist/server/` and static assets
at `dist/client/`.

You need a Cloudflare account. These commands run on your machine (they require
an interactive login or a `CLOUDFLARE_API_TOKEN`), not inside a CI sandbox.

## Option A — OpenAI Apps hosting (if this project was scaffolded there)

This repo carries `.openai/hosting.json` (`project_id: appgprj_…`, `d1: "DB"`),
meaning it was scaffolded by the OpenAI app builder, which provisions the
Cloudflare Worker + D1 for you. If you have that project, use its **Publish**
flow — it applies migrations and deploys without manual wrangler steps.

## Option B — Manual Cloudflare deploy with wrangler

### 1. Authenticate
```bash
npx wrangler login            # or export CLOUDFLARE_API_TOKEN=<token with Workers+D1 edit>
npx wrangler whoami           # confirm the account
```

### 2. Create the D1 database and record its id
```bash
npx wrangler d1 create acc-db
# → copy the printed database_id (a real UUID)
```

### 3. Apply the schema migrations (in order)
The schema lives in `drizzle/` (0000 … 0010). Apply every file, oldest first,
to the **remote** database:
```bash
for f in $(ls drizzle/*.sql | sort); do
  npx wrangler d1 execute acc-db --remote --file "$f"
done
```
`0010_deep_random.sql` rebuilds `users` for guest access and drops
`oauth_states`; it preserves any existing verified users.

### 4. Build
```bash
npm ci
npm run build            # emits dist/server (Worker) + dist/client (assets)
```

### 5. Point the Worker at your real D1 id and deploy
The build writes a placeholder `database_id` into `dist/server/wrangler.json`.
Replace it with the id from step 2, then deploy from that directory:
```bash
# macOS/BSD sed: use `sed -i ''`. Linux: `sed -i`.
sed -i "s/00000000-0000-4000-8000-000000000000/<YOUR_DATABASE_ID>/" dist/server/wrangler.json
cd dist/server && npx wrangler deploy
```
Wrangler prints the live URL (e.g. `https://acc-accounting-workspace.<subdomain>.workers.dev`).

> Tip: to keep the id across rebuilds, set it in `.openai/hosting.json` tooling
> or add a top-level `wrangler` config; the generated `dist/server/wrangler.json`
> is regenerated by each build.

### 6. Configuration (all optional — ACC opens anonymously without any of these)
Set only what you use, as Worker secrets:
```bash
npx wrangler secret put APP_BASE_URL          # your exact https origin, no path
# AI (optional): OPENAI_API_KEY, OPENAI_MODEL, NVIDIA_* …
# Market Intelligence (optional): REDDIT_*, YOUTUBE_* + compliance flags
```
There is **no** Google/auth provider to configure — access is anonymous guest
sessions.

### 7. Smoke test the live URL
Open ACC → onboarding (3 fields) → post a transaction → reverse → export →
delete in a disposable workspace → sign out. Confirm CSP/security headers.

## Rollback
See the README "Rollback" section. A code rollback never reverses an applied
additive migration; use D1 Time Travel for a genuine data-recovery event.
